ЗАПУСК DEEPSEEK FLASH / PRO
===========================

Этот файл фиксирует актуальный способ запуска DeepSeek из `/work/deepseek`.
Старый документ был про интерактивный запуск как отдельный сценарий; сейчас
основные режимы два: прямой Codex CLI через `bin/deepseek` и очередь задач
через `bin/orchestrate`.

## 1. Правило запуска владельца от 24.10.2026

Для разрешённых задач всегда используйте штатный запуск с `--dangerous`.
Не добавляйте собственные UID, профили, Landlock/bubblewrap/контейнеры или
ограничивающие launch-hook. Не переопределяйте `DEEPSEEK_CODEX_BIN` и
`DEEPSEEK_CODEX_HOME`: используйте обычную конфигурацию фреймворка.

Если владелец сообщил, что доступ готов, запускайте задачу без предварительных
`--check`, `doctor`, `balance` и пробных API-запросов. Эти команды нужны только
при отдельном запросе диагностики или конкретной ошибке.

Все прикладные тесты, SQL, БД, зависимости, сборки и browser QA — только на
авторизованном VPS. WSL/Windows — управляющий клиент. Локальные стенды запрещены.

Ключ берется из `DEEPSEEK_API_KEY` или из файла
`/home/hgff/api deepseek.txt`. Значение ключа нельзя печатать, коммитить или
вставлять в отчеты.

## 2. Прямой интерактивный запуск

Flash:

```bash
/work/deepseek/bin/deepseek --project /work/my-project --model deepseek-flash --dangerous
```

Pro:

```bash
/work/deepseek/bin/deepseek --project /work/my-project --model deepseek-v4-pro --dangerous
```

Если `--model` не указан, `bin/deepseek` использует `deepseek-v4-pro`.
Если `--project` не указан, используется текущий каталог терминала.

Продолжить последний диалог в том же проекте:

```bash
/work/deepseek/bin/deepseek resume --project /work/my-project --last --model deepseek-flash --dangerous
/work/deepseek/bin/deepseek resume --project /work/my-project --last --model deepseek-v4-pro --dangerous
```

Штатный широкий запуск разрешённой задачи использует `--dangerous`:

```bash
/work/deepseek/bin/deepseek --project /work/my-project --model deepseek-v4-pro --dangerous
```

Из root shell можно запускать коротко, как `codex`/`glm`; если `--project` не
указан, проектом будет текущий каталог:

```bash
sudo -i
cd /work/my-project
deepseek --model deepseek-flash --dangerous
deepseek --model deepseek-v4-pro --dangerous
```

Владелец дал постоянное разрешение на этот режим для поставленных задач.
Широкие права процесса не меняют границы задачи и ограничения production.

## 3. Очередь задач через orchestrate

Проект должен иметь одну из двух форм:

- `GOAL.md`, если DeepSeek должен сам составить задачи;
- `tasks/T*.md`, если задачи уже подготовлены Codex, человеком или другим
  процессом.

### 3.1. DeepSeek сам планирует и выполняет

Flash для планировщика и работников:

```bash
cd /work/deepseek
bin/orchestrate start \
  --project /work/my-project \
  --controller deepseek \
  --goal /work/my-project/GOAL.md \
  --model deepseek-flash \
  --routing economy \
  --idle-exit --dangerous
```

Pro для планировщика и работников:

```bash
cd /work/deepseek
bin/orchestrate start \
  --project /work/my-project \
  --controller deepseek \
  --goal /work/my-project/GOAL.md \
  --model deepseek-v4-pro \
  --routing quality \
  --idle-exit --dangerous
```

Смешанный вариант: планировщик Pro, а работники выбираются политикой routing:

```bash
cd /work/deepseek
bin/orchestrate start \
  --project /work/my-project \
  --controller deepseek \
  --goal /work/my-project/GOAL.md \
  --controller-model deepseek-v4-pro \
  --model auto \
  --routing balanced \
  --idle-exit --dangerous
```

### 3.2. Задачи уже подготовлены

Flash для всех задач с `Model: auto`:

```bash
cd /work/deepseek
bin/orchestrate start \
  --project /work/my-project \
  --controller codex \
  --model deepseek-flash \
  --idle-exit --dangerous
```

Pro для всех задач с `Model: auto`:

```bash
cd /work/deepseek
bin/orchestrate start \
  --project /work/my-project \
  --controller codex \
  --model deepseek-v4-pro \
  --idle-exit --dangerous
```

Автовыбор модели по `Complexity:` в задаче:

```bash
cd /work/deepseek
bin/orchestrate start \
  --project /work/my-project \
  --controller codex \
  --model auto \
  --routing balanced \
  --idle-exit --dangerous
```

Политика routing при `--model auto`:

- `economy`: low/medium/high -> Flash;
- `balanced`: low/medium -> Flash, high -> Pro;
- `quality`: low -> Flash, medium/high -> Pro.

Явная строка `Model: deepseek-flash` или `Model: deepseek-v4-pro` внутри
`tasks/T*.md` имеет приоритет над `--model auto`.

Для запуска очереди с широкими правами добавьте `--dangerous`:

```bash
cd /work/deepseek
bin/orchestrate start \
  --project /work/my-project \
  --controller codex \
  --model deepseek-v4-pro \
  --dangerous \
  --idle-exit
```

## 4. Мониторинг и остановка

```bash
cd /work/deepseek
bin/orchestrate status --project /work/my-project
bin/orchestrate usage --project /work/my-project
bin/orchestrate models --project /work/my-project
bin/orchestrate attach --project /work/my-project
bin/orchestrate stop --project /work/my-project
```

`--idle-exit` завершает tmux-сессию после выполнения всей очереди. Без него
оркестратор остается ждать новые задачи.

После прерванной или упавшей задачи автоматического повтора нет: задача могла
уже изменить файлы. Исправьте причину и создайте следующую задачу.

## 5. Какой режим выбирать

- Для быстрого анализа, поиска, простых правок и дешевого прогона используйте
  `deepseek-flash`.
- Для сложного планирования, многофайловой реализации, спорной диагностики и
  задач с большим риском ошибки используйте `deepseek-v4-pro`.
- Для обычной очереди, где в задачах есть `Complexity:`, используйте
  `--model auto --routing balanced`.
- Для максимального качества очереди используйте
  `--model auto --routing quality` или явный `--model deepseek-v4-pro`.

Проверено по текущим wrapper-скриптам `/work/deepseek/bin/deepseek` и
`/work/deepseek/bin/orchestrate`.
